# 锐度归一化实施方案 (down128) —— ❌ 已验证否决，勿再实施

> 2026-07-24 · 状态：**已否决并回滚**

## ⛔ 否决结论（2026-07-24，先读这一段）

本方案**问题定义正确、解法错误**。小鸟锐度虚高确实存在（海鹦批
spearman ρ(锐度,ROI) = **−0.526**），但 down128 解决不了它，理由如下。

**1. 它压根没碰问题人群。** down128「只降不升」，ROI ≤128px 完全不处理，
而海鹦批 30% 的照片正落在这个区间。实测最小档（ROI 中位 81px）补偿前后
分数**分毫未动**（615.1 → 615.1）；它抬高的是大鸟（Q4 档 517 → 680）。
相对排序上等价，但小鸟的绝对分一分没降——用户看到的问题原样保留。

**2. 它在别的题材上凭空制造反向偏差。**

| 批次 | 头部 ROI 中位 | 旧公式 ρ | down128 后 ρ |
|---|---|---|---|
| 海鹦批 | 219px | −0.526 | **+0.566** |
| 08-20 | 401px | +0.139 | +0.392 |
| 08-23 | 361px | −0.132 | +0.350 |

08-23 批旧公式 |ρ|=0.13，**本就优于本方案给自己定的目标值 0.095**，
down128 把它推到 +0.35。

**3. 代价是真金白银的信息损失。** 把 1292px 的头压成 128px 丢掉 99% 像素，
破坏大 ROI 之间的判别力；且所有分数尺度改变，被迫全套重标阈值
（305/425/550 那批「阶段A临时值」就是这么来的）。

**4. 三轮共 88 组人工盲评拿不出任何一处干净胜绩。** 表面上的胜负经分层后
全部由混淆变量解释：尺度争议组「胜 15:4」源于它偏好大 ROI 与用户偏好共线
（新公式偏好的那张 24/24 都是大 ROI）；同尺寸对照组的「败 0:5 / 9:0」则
几乎全部来自单一鸟种（鸡尾鹦鹉，10 分钟内同一快门的一次拍摄，等于 1 个
独立样本）。按鸟种计票后 **新 4 : 旧 3，p=0.50**，完全打平。

**结论：两个公式的差异在人眼可辨识度之下，而 down128 有确定的代价和
被证伪的收益。** 已回滚，`NORM_ROI_SIZE` 与 `test_sharpness_normalization.py`
一并删除。

### 正确的解法（见取代方案）

受控缩放实验（同一 ROI 缩放到 512~45px，画质无任何真实变化）测得
**raw ∝ s^−0.641**，即纯几何伪影 **87.4 分/e倍尺寸**。直接在 log 归一化后
按此值**解析扣除**即可：不碰图像、零信息损失、只减不加，ROI ≥300px 一分不动，
故阈值语义不变、无需重标。海鹦批 ρ 由 **−0.526 → +0.052**，08-23 由
**−0.132 → +0.003**。

## 以下为原方案原文（仅作存档，勿实施）

> 2026-07-24 · 关联审计发现 B1（锐度尺度依赖）· 状态：~~待批准~~ 已否决

## 一、动机与证据

现行 `_calculate_sharpness` 用 Tenengrad = `Σg² / N`，是**梯度密度**不是总量。
鸟的头部 ROI 像素越小，分母 N 按 1/k² 暴跌，而分子 Σg² 只降到约 1/k^1.1，
相除导致**小鸟/远拍锐度虚高、近拍大鸟反而偏低**（密度效应，机理已实测自洽）。

真实批次（433 张，JJ-2TB/20260712-0719 2）证据链：

| 检验 | 现行 | down128（只降不升到 128px） |
|---|---|---|
| 锐度 vs ROI 尺寸相关性 \|ρ\| | 0.363 | **0.095**（依赖降 74%） |
| 与现行排序一致性 | — | 0.858（未大幅打乱） |
| 零分数 | 0 | 0 |
| **人工盲评 14 组翻转对** | 胜 1 | **胜 13（93%，p≈0.002）** |

盲评是决定性证据：在两个公式打架的照片对上，人眼 13:1 站在 down128 一边，
且系统性地选了「现行判低分的大 ROI」那张——直接印证密度效应的危害。

## 二、核心代码改动

**唯一改动点**：`core/keypoint_detector.py::KeypointDetector._calculate_sharpness`，
在 `boundingRect` 取出 ROI 之后、`Sobel` 之前，插入「只降不升到 128」：

```python
NORM_ROI_SIZE = 128   # 类常量；盲评 + |ρ| 双指标最优（见本方案 §一）

# ...取出 roi, roi_mask 之后：
side = max(roi.shape[:2])
if side > NORM_ROI_SIZE:                       # 只降不升：ROI≤128 保持原样，不上采样
    roi = cv2.resize(roi, (NORM_ROI_SIZE, NORM_ROI_SIZE), interpolation=cv2.INTER_AREA)
    roi_mask = cv2.resize(roi_mask, (NORM_ROI_SIZE, NORM_ROI_SIZE),
                          interpolation=cv2.INTER_NEAREST)
```

**为什么是 128 且只降不升**（横评 10 方案结论）：
- 强制缩放（含上采样）全线把 \|ρ\| 推到 +0.7~0.86、排序一致性崩到 0.07~0.27
  ——上采样是插值伪影，纯制造噪声。
- 只降不升 128：\|ρ\|=0.095 最低，排序一致性 0.858，零分数 0。64 太浅、
  192+ 几乎不触发（真实 ROI 中位仅 99px）。

## 四、下游影响与阈值重标

### 4.1 受影响的三个阈值来源（都要重标）

| 常量 | 位置 | 现值 | 处置 |
|---|---|---|---|
| `SKILL_PRESETS` sharpness | `core/skill_presets.py` | 300/380/520 | **重标（见 §五）** |

### 4.2 整图路径的副作用（需知会，无功能影响）

`photo_processor.py:1582` `calculate_rejected_quality_detail` 用**整图 full_mask**
调 `_calculate_sharpness`，归一化会把数千 px 的整图也降到 128。
影响：**无鸟/早拒照片的展示锐度值会变**，但这些照片评级恒为 -1/0，
不参与评星与 burst 排序，纯展示。方案默认让整图路径一起归一化（更可比），
如需保留旧展示值可给该路径传参跳过——建议不特殊处理。

### 4.3 report.db 历史值不可比（需知会）

上线后新批次的 `head_sharp` 是归一化值，与旧批次的旧公式值**不在同一尺度**。
结果浏览器若跨批次混排锐度会错乱。burst_ranking 是**批内**排序，不受影响。
建议：ChangeLog 明确「历史批次锐度值与新版不可直接比较」。

## 五、档位重标流程（用户已选「重新定档位手感」）

不沿用旧占比，借此机会重新校准三档松紧。分两阶段：

**阶段 A（代码先行，可立即做）**：落地 §二 归一化 + 用「保持各档占比不变」
的临时阈值（300→305 / 380→425 / 520→552，本批反推）作为占位，保证不回归。

**阶段 B（标定，依赖用户素材）**：
1. 用户提供 3~5 批不同题材照片（近距大鸟 / 远距小鸟 / 飞版 / 高 ISO 各覆盖）
2. 我跑归一化锐度，给每批的 score 分布 + 分位表
3. 用户按「这批里几星该占多少」或盲评定三档最终值
4. 固化到 `SKILL_PRESETS`，同步 `rating_quota` 硬门槛/兜底
