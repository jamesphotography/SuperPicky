# 实验室页面 + 多目录选鸟 设计 / Labs Page + Multi-folder Culling Design

日期 / Date: 2026-11-07
状态 / Status: 已定稿待审阅（2026-11-07 用户确认两项拍板） / final draft for review
草图 / Mockup: `.superpowers/brainstorm/*/content/lab-multifolder.html`（本地，不入库）

## 1. 为什么做 / Why

**界面太杂，新手看着累。** 结果浏览器的"导出"菜单里有"生成报告""导出到 eBird"。用户（项目作者）的判断是：用的人很少，功能本身问题也多，不该摆在新手面前。

**有一类先锋功能需要一个"先放出来试"的地方。** 第一个就是"多目录选鸟"：现在一次只能选一个目录（或一个父目录，自动扫它下面的子目录）。拍了几个地点、放在不同盘或不同父目录下的照片，只能分几次处理。

所以要在设置中心加一页"实验室"：
- 放"更多功能"：已有但不想默认露面的功能，即报告和 eBird 导出。
- 放"实验功能"：新的、还在打磨的功能，即多目录选鸟。

所有开关**默认关闭**。

Labs page: hide rarely used, problem-prone features (report, eBird export) by default to simplify the UI for newcomers, and give experimental features (first: multi-folder culling) an opt-in home. Everything defaults to off.

## 2. 目标 / 非目标 / 反目标

**目标 / Goals**
1. 设置中心新增"实验室"页，分"更多功能"和"实验功能"两段，每项一个开关，默认关闭。
2. 报告、eBird 导出的入口由开关控制：关闭时界面上完全看不到，打开后与现在完全一样。
3. 多目录选鸟：可以从任意位置（跨盘、跨父目录）添加多个目录，一次点"开始"依次处理。**每个目录的处理结果与单独选它处理时完全相同。**
4. 结果浏览器**不合并显示**：顶部一排目录标签，一次看一个目录。
5. "最近目录"里，一次多选的目录记为一条，点它恢复整组。

**非目标 / Non-goals**
- 不照顾老用户（用户拍板）：升级后报告和 eBird 一样默认关闭，不做迁移，不弹提示。
- 不改报告、eBird 导出本身的代码和行为，只控制入口是否显示。
- 不改命令行（`superpicky_cli.py`）。
- 不做跨目录合并统计、合并浏览、跨目录连拍或去重。
- 不改结果浏览器现有的"父目录下多批次合并浏览"（`_resolve_directories` / `_ask_which_batches`）。那是浏览器自己打开目录时的已有功能，与本设计无关。

**反目标（做成这样就算失败）/ Anti-goals**
- 多目录模式下，某个目录的结果和单独处理它时不一样（星级、移动位置、DB、XMP 有任何差异）。
- 关闭"多目录"开关后，单目录的界面或行为有任何变化。
- 实验室开关关闭时，还能在任何地方看到报告或 eBird 导出的入口。
- 处理多目录时，因为某个目录出错，导致其他目录没处理或结果被破坏。

## 3. 约束 / Constraints

- 按 CLAUDE.md 设置中心约定：开关存放在 `advanced_config`（`DEFAULT_CONFIG` + property/setter），页面加入 `PAGE_ORDER`，不得另建 json 文件。
- 跨平台：不同目录可能在不同盘符（Windows 的 `C:` 和 `D:`）上，**任何地方都不能对两个用户目录求相对路径**（`os.path.relpath` 跨盘会抛 `ValueError`）。
- 三语界面（zh_CN / zh_TW / en_US）都要配文案。
- 恢复默认设置：实验室开关是普通用户设置，**不进** `PRESERVE_ON_RESET`，恢复默认就会关掉。多目录的"最近目录组"属于历史记录，**要进** `PRESERVE_ON_RESET`，与 `recent_directories` 一致。
- 改动后必须在真实窗口（cocoa）上看界面，不能只看 offscreen 截图（见进度条被压扁的教训）。

## 4. 已经定下的做法 / Decided

### 4.1 实验室页面

- 设置中心新增一页，标题"实验室 / Labs"，在 `PAGE_ORDER` 中排在"外部应用"之后、"关于"之前。
- 页面分两段：
  - **更多功能 / More features**（"默认关闭，开启后对应按钮才出现"）
    - 生成报告：控制结果浏览器"导出"菜单里的"生成报告"。
    - 导出到 eBird：控制"导出"菜单里的"导出到 eBird"。
  - **实验功能 / Experimental**（"还在打磨，可能变化"）
    - 多目录选鸟，旁边带"实验"小标签。
- 新配置字段，默认全部为 `False`：
  - `lab_report_export`
  - `lab_ebird_export`
  - `lab_multi_folder`
- 开关改动后立即生效：已经打开的结果浏览器"导出"菜单要跟着显示或隐藏，不需要重启。
- 如果"导出"菜单里所有项都被隐藏，则隐藏整个"导出"按钮。在 Windows 上，Apple Photos 那一项本来就不存在。

### 4.2 多目录：主界面

- `lab_multi_folder` 关闭时：主界面目录栏与现在**完全一致**。
- 开启时：目录栏变为列表。
  - 每行显示路径和照片数，带移除按钮。
  - 下方有"＋ 添加目录…"按钮，以及"共 N 个目录 · M 张"的合计。
  - 列表里只有 1 个目录时，行为等同单目录。
- 添加时的检查：
  - 同一目录重复添加：忽略。
  - 新目录与已有目录**互相包含**（一个是另一个的子目录）：拒绝，并提示原因，否则会重复处理。
  - 危险目录（`is_dangerous_root`）：添加时就拒绝，提示与现在相同。
  - 没有照片的目录：添加时提示，不加入列表。

### 4.3 多目录：处理

**开始前的询问只弹一次（用户拍板 2026-11-07）。** 点"开始"后、队列启动前，先检查列表中每个目录的状态：
- **上次没处理完**（有断点续传状态）：一律接着处理，对应单目录的"继续"。
- **已经处理过**（有 `report.db`、无断点状态）：默认跳过；勾选"全部重新处理"时，对应单目录的"重新处理"，即先撤销上次的文件移动再重跑。

只要存在上面任一类目录，就弹**一个**确认框把它们列出来，并提供"全部重新处理"勾选框。处理中途不再弹任何询问。"与单独处理结果相同"的对照标准，就是单目录下做出同样选择时的结果。

**其他开始前提示也只弹一次（我的决定）：**
- 存储卡（可移动盘）警告：列出位于存储卡上的目录。
- 识鸟国家提示、开始确认、首次视频提示：各弹一次。
- ExifTool 健康检查只做一次；照片预扫描对每个目录都做。

**处理顺序：**
- 点"开始"后**按列表顺序逐个**处理（用户拍板 2026-11-07）：一个目录完全处理完，包括整理、移动和写元数据，才开始下一个，不并行。
- 列表顺序就是用户添加目录的顺序。从"最近目录"恢复的整组，按当时保存的顺序排列。对每个目录，走的流程与"用户单独选了这个目录然后点开始"相同：
  - 它自己的子目录扫描（父目录批量模式照旧）；
  - 它自己的 `report.db`、断点续传状态、整理 / 移动、XMP。
- 多个目录之间不共享任何状态。日志里每个目录开头打一行"[i/N] 路径"。
- 进度条反映全部目录的总进度。
- 点"停止"：停掉整个队列。已处理完的目录保留结果，正在处理的目录按现有停止逻辑处理，后面的目录不再开始。
- 某个目录处理时出错：日志记下这个目录名和错误，**跳到下一个目录继续**，最后在完成信息里列出出错的目录。

**全部处理完以后（我的决定）：**
- 只收尾一次：给一份汇总，逐个目录列出张数、星级分布、跳过或出错情况；提示音只响一次；识鸟面板只刷新一次。
- 打开结果的方式：保留预览图时，打开结果浏览器一次，带目录标签；不保留预览图时，只打开**第一个**目录的文件夹，不弹 N 个访达或资源管理器窗口。

**重置与重新处理（用户拍板 2026-11-07）：**
- 多目录时，"重置目录"和"重新处理"作用于**整个列表**，确认框里把所有目录列出来，确认一次。
- 想只重置其中一个目录，先把其他目录从列表里移除。

### 4.4 多目录：结果浏览器

- 不合并。浏览器顶部多一排目录标签，每个标签对应列表中的一个目录，显示目录名和照片数。
- 点标签 = 以该目录调用现有的打开目录逻辑，效果与现在打开单个目录完全一样。
- 什么时候出现标签（我的决定）：只要主界面列表里有多个目录，打开结果浏览器就出现，包括从"最近目录"恢复的整组、没有重新处理就直接点"查看结果"的情况。
- 哪些目录有标签：有结果（`report.db`）的目录才有，包括中途停止或出错但已有部分结果的目录。没有任何结果的目录不出标签。
- 单目录时不显示标签。

### 4.5 最近目录

- 一次多选处理的目录组，在"最近目录"菜单里算一条，显示为"N 个目录：A、B、C"（过长时截断）。
- 点击后把这组目录全部放回列表；不存在的目录（例如外接盘没插）灰显并跳过，不报错中断。
- 存储：新字段 `recent_directory_groups`（列表的列表）。**不改** `recent_directories` 的格式，否则降级到老版本时会读到非字符串条目而出错。
- 判重（我的决定）：目录集合相同就算同一组，不管顺序；再次使用时移到最前。最多保留 10 组，与 `recent_directories` 的上限一致。
- 与开关的配合（我的决定）：
  - 多目录开启时，点"最近目录"里的单个目录，会**替换**整个列表。
  - 多目录关闭时，"最近目录"里不显示目录组。
  - 列表里有多个目录时关掉开关，只保留第一个目录，界面回到单目录。

## 5. 留给实现者 / Left to the builder

- 实验室页面、目录列表、浏览器标签的具体控件和样式：沿用设置中心与浏览器的现有风格，例如开关用 `checkbox_indicator_qss`，标签参考浏览器现有的筹码样式。
- 多目录状态放在 `main_window` 的哪里，以及如何与现有 `directory_path`（约 60 处）共存。方向是：单目录路径完全不动，多目录另走一条薄的"队列"路径，复用现有单目录处理。
- 日志、提示的具体措辞。
- 测试怎么拆。至少要覆盖：同一目录单独处理与在多目录中处理结果一致；跨盘路径不求相对路径；开关关闭时入口不可见；恢复默认会关掉开关、保留目录组。
